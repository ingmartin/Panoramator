# Публичный Roadmap

Этот roadmap написан для посетителей репозитория. Он объясняет, что уже достаточно стабильно для практического использования, что сознательно вынесено за рамки проекта и какие шаги сильнее всего повысят публичную ценность репозитория.

## Текущее Позиционирование

* `build` предназначен для панорам сцены при примерно линейном движении или повороте камеры на месте.
* `unwrap` предназначен для облёта одного объекта, когда нужен surface map, а не панорама окружающей сцены.
* Орбитальный захват намеренно не трактуется как ещё один режим `build`.

## Следующие Публичные Улучшения

### 1. Более сильная demo-подача

* добавить в `README.md` реальные before/after изображения;
* добавить короткие GIF-версии публичного demo pack;
* сделать один comparison-раздел: `build` против generic stitching tools.

### 2. Более воспроизводимые примеры

* добавить `examples/` с готовыми конфигами;
* добавить по одной документированной команде для `linear`, `rotation`, `unwrap-cylinder`, `unwrap-curved`;
* показать краткий блок с ожидаемой диагностикой для каждого примера.

### 3. Более сильные сигналы доверия

* опубликовать компактную benchmark-таблицу с успешными и проблемными кейсами;
* яснее документировать неподдерживаемые capture-сценарии;
* делать визуальные release notes, где у каждого релиза есть хотя бы одно изображение или видео.

### 4. Более простой вход для контрибьюторов

* пометить несколько задач как `good first issue`;
* документировать архитектурные решения вокруг frame selection, projection и unwrap;
* описать публичную политику fixture-данных: что синтетическое, а что конфиденциальное.

## Явные Non-Goals

* рассматривать орбитальный облёт объекта как ещё один режим scene panorama в `build`;
* делать вид, что private acceptance-видео можно публиковать;
* маскировать известные ограничения захвата слишком широкими маркетинговыми формулировками.
